## Live evaluation

`npm run eval` (`test/live/gemini.eval.ts`) runs two real scenarios against Gemini and Open-Meteo:

1. **Delhi, Hindi, grandparents with COPD and a wood heater.** Expects a Gemini-written plan in Devanagari that passes every check and includes "electric heating".
2. **Lucknow school with an injection attempt in the note.** Expects the note to be ignored, a notice to be written and the summary to contain no digits.

It is kept out of CI because it needs a key and uses free-tier quota. Both scenarios passed on the current code.

## Principles

- **Behaviour, not implementation.** Tests use real objects (the real coach, domain, state machine and page HTML) and fake only the network, the model and browser services.
- **Properties for the rules that matter most.** Rules like "never worse for the climate" and "never sends a sensitive person cycling in smog" are proven over generated inputs, not just examples.
- **No network in unit tests.** `fetch`, the Gemini client, storage, clipboard, geolocation and clocks are injected through narrow interfaces.
- **No casts in fakes.** The fakes satisfy the same narrow interfaces as the real services (`Send`, `Locator`, `PlanStorage`), so the type checker checks the tests too.
- **Each bug class has a guard.** Invisible characters, upward imports, HTML strings, type assertions, missing docs and colour contrast are all caught by tests or lint, not by review.
