# Accessibility

Target: **WCAG 2.2 AAA** wherever it applies.

| Need                                               | What HazeGuard does                                                                                                                                                                                                                  | Where                                                    |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| Contrast (1.4.6 AAA)                               | Every text pairing is **at least 7:1** in light and dark schemes, including dark text on every air-band tint. Borders, focus rings and chart bars are at least 3:1. **Checked by arithmetic in a test**                              | `web/styles/tokens.css`, `test/quality/contrast.test.ts` |
| Colour is never the only signal (1.4.1)            | Every band is named in text ("Very poor now"). The 24-hour strip is decorative (`aria-hidden`) and duplicated by a real table                                                                                                        | `web/render-air.ts`                                      |
| Structure (1.3.1)                                  | Landmarks (header, main, footer); one `h1`, then `h2`/`h3`/`h4` in order; fieldsets with legends; tables with captions and `scope` headers; lists for lists                                                                          | `public/index.html`, renderers                           |
| Labels and instructions (3.3.2)                    | Every control has a visible label. Hints are linked with `aria-describedby`. Required fields say "(required)" in text                                                                                                                | `public/index.html`, `web/trip-rows.ts`                  |
| Error identification and suggestion (3.3.1, 3.3.3) | Server field errors appear in a focused **error summary** with links to each field. The fields get `aria-invalid`, and inline messages say how to fix the problem ("Use at least 0.1 km.")                                           | `web/form-errors.ts`, `src/http/plan-request.ts`         |
| Status messages (4.1.3)                            | Polite live regions announce added and removed trips, the location status, progress and the result                                                                                                                                   | `web/form-controller.ts`, `web/main.ts`                  |
| Busy state (4.1.2)                                 | While a plan is being made, the form and plan regions carry `aria-busy="true"` and the submit button is disabled, so screen readers wait for the finished content                                                                    | `web/main.ts`                                            |
| Forced colours and high contrast                   | In Windows high-contrast and other forced-colour modes, cards, fieldsets, the reading and the 24-hour strip keep visible system-colour boundaries. With `prefers-contrast: more`, secondary text uses full ink and lines are heavier | `web/styles/plan.css`                                    |
| Figures with labels (1.3.1)                        | The impact figures are a description list: each value (`<dd>`) is paired with what it measures (`<dt>`), so no bold paragraph looks like a heading without being one                                                                 | `web/render-impact.ts`                                   |
| Focus                                              | A skip link; focus moves to the error summary, the plan, the new trip field or the Add button as appropriate; a 3 px outline with an offset on every focusable element                                                               | `web/styles/base.css`, `web/main.ts`                     |
| Target size (2.5.5 AAA)                            | Buttons, inputs, selects and the `summary` toggle are at least 44 CSS px tall; every checkbox and radio has a label at least 44 px tall that toggles it                                                                              | `web/styles/*.css`                                       |
| Label in name (2.5.3)                              | Remove buttons read "Remove trip 2"; the visible text and the accessible name match                                                                                                                                                  | `web/trip-rows.ts`                                       |
| Language of parts (3.1.2)                          | Gemini's Hindi text carries `lang="hi"`, and the computed facts in a notice carry `lang="en"`                                                                                                                                        | `web/render-*.ts`                                        |
| Reading level (3.1.5)                              | Plain language, short sentences, abbreviations explained (NAQI, PM2.5), and lines capped at 68 characters                                                                                                                            | content, `--measure`                                     |
| Reflow and text spacing (1.4.10, 1.4.12)           | Single column down to 320 px, then two columns from 60 rem. Wide tables scroll inside keyboard-focusable, labelled regions. No fixed heights on text                                                                                 | `web/styles/form.css`, `plan.css`                        |
| Motion (2.3.3)                                     | No animation; smooth scrolling only when `prefers-reduced-motion: no-preference`                                                                                                                                                     | `web/styles/base.css`                                    |
| Timing (2.2.3 AAA)                                 | Nothing times out on the user. The plan request waits up to 45 s, then explains                                                                                                                                                      | `web/api.ts`                                             |
| Print                                              | A print stylesheet hides the form and controls and keeps cards whole. **Print or save as PDF** button                                                                                                                                | `web/styles/plan.css`                                    |
| No-JS                                              | A `<noscript>` message explains why scripting is needed                                                                                                                                                                              | `public/index.html`                                      |

## How it is tested

- **axe-core in jsdom** runs on the real page before and after a plan is rendered, with **every WCAG 2.0, 2.1 and 2.2 rule at A, AA and AAA, plus best practices and experimental rules**. Result: 0 violations (`test/web/page.test.ts`).
- **axe-core in a real browser (Microsoft Edge)**, with the same rule set plus AAA enhanced contrast (`color-contrast-enhanced`), on the empty form and on a full community plan with every `<details>` open, in light and dark. Result: 0 violations.
- **Contrast** is computed from the CSS tokens for 50 pairs in both colour schemes (`test/quality/contrast.test.ts`).
- **Manual check** in the browser: keyboard-only use, a 320 px viewport and dark mode.
